FIRST CODE IN THE TALK. This is what was running behind block 2's slides, and it has just finished.

The 6809 has a MUL instruction and it multiplies two UNSIGNED bytes. The model needs signed multiplication. The first version did it a bit at a time: correct, easy to explain, and 38.6 million instructions for the run.

This is what replaced it. Split the 16-bit operand, two MULs, add the halves. 15.8 million instructions. The model is bit-for-bit identical: not one output changed.

THE REGISTER COLUMN is a captured training step, not an invention: SINCLAIR's weight update at epoch 5, context 26 times error -244. The MUL rows split D into A : B, so both of addb's operands are on screen before it runs: the 230 is the second MUL's B, and the stored 1 is the first product's high byte, two rows up. Two things to point at. B holds 12 and then 255 — those are -244's two bytes taken unsigned, because MUL never sees a sign. And the second MUL's A half, 25, is never stored: the low sixteen bits are the whole answer. The product this walk ends on, -6344, is the exact gradient the shift slides are about to divide by sixteen. One update, traced end to end.

THE POINT, and it is a human one: the learning algorithm did not change. Somebody understood both the mathematics and the machine, and that is what turned a correct experiment into something you can watch happen.

The tests are what made that safe. You cannot optimise aggressively without them; you can only hope.

OPTIONAL DEPTH. Drop this first if the run finishes early.

MUL is unsigned, so if the factor was negative its unsigned form is 256 too large. Subtract the multiplier's low byte from the high byte of the result and it is correct again.

Worth showing because it is the kind of detail that decides whether a thing is possible on this machine at all, and because it is five instructions.

The register column runs the same worked numbers as the next slide, so the bit rows there are these registers drawn in binary. The dots row says what the elided code left behind: this example's own two MULs made 135 x 60 = 8100, bytes 31 and 164 — that is where lda's 31 comes from.

WHERE THE 60 COMES FROM: suba 1,x reaches back to the multiplier, still sitting at X — the same 1,x the MULs loaded from. Nothing new arrives for the fix; it reuses an input it already had. And 164 survives to the last line untouched: the correction only ever edits the high byte.

Note the factor here is negative where the captured step's was not — that is exactly why the captured step skipped this correction and this example needs it.

Two's complement: a leading 1 means negative. These same sixteen bits read as 59,192 if you take them as unsigned.

asra keeps that top bit and drops the bottom one into the carry; rorb carries it in to B's top, then drops B's bottom bit into the same carry, uncollected: the carry out. Watch the left edge: the 1 copies itself downward, which keeps the value negative as it halves.

Every number in this model is a whole number, because this machine has no other kind. Effectively, we are doing quantization to 16 bits. The 4-bit models on phones make the same trade.

IF FINE-TUNING COMES UP: fine-tuning is more of exactly this — training that moves the weights, on data somebody chose. A company fine-tuning a model on its own documents is choosing training data, and it inherits every trap on this slide, ordering included.
